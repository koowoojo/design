# UX-KIT 설치 파일

> **사용법**: 이 파일을 커서 채팅에 첨부하고 **"적용시켜줘"** 라고만 입력하라.
> 설치 후에는 아무것도 하지 않아도 된다. 화면 설계를 요청하면 자동으로 발동한다.

---

## 🤖 에이전트 지시 — 이 파일을 받으면 즉시 아래를 실행하라

사용자가 "적용", "설치", "세팅", "apply" 중 무엇이라 말하든 이 절차를 실행한다.
사용자에게 되묻지 마라. 확인 없이 진행하고, 끝나면 결과만 보고하라.

**만들 파일은 3개다.** 하나라도 빠지면 동작하지 않는다.

### 1단계. 진입점 규칙 생성

- 경로: `.cursor/rules/ux-kit-entry.mdc`
- 내용: **`BLOCK A`** 의 내용을 그대로.
- 주의:
  - 확장자는 반드시 `.mdc`. `.md` 로 만들면 커서가 무시한다.
  - 맨 앞 `---` frontmatter를 빠뜨리지 마라.
  - **`alwaysApply: true` 를 `false` 로 바꾸지 마라.** 이 파일은 상시 로드되는 것이 목적이다.
  - 짧게 유지하는 것이 설계 의도다. 내용을 덧붙이지 마라.
  - `.cursor/rules/` 가 없으면 만든다. 파일이 있으면 `.bak` 백업 후 덮어쓴다.

### 2단계. 본체 규칙 생성

- 경로: `ux-kit/UX-UI-RULES.md`
- 내용: **`BLOCK B`** 의 내용을 그대로.
- 주의:
  - 이건 커서 규칙 파일이 **아니다.** 일반 마크다운이다. `.cursor/rules/` 에 넣지 마라.
  - 진입점(BLOCK A)이 이 파일을 읽어오는 구조다. 경로를 바꾸면 연결이 끊긴다.
  - **요약하거나 압축하지 마라.** 그대로 복사한다.

### 3단계. 조직 컨텍스트 생성

- 경로: `ux-kit/context.md`
- 내용: **`BLOCK C`** 의 내용을 그대로.
- **파일이 이미 있으면 건드리지 마라.** 사용자가 채운 내용을 덮어쓰면 안 된다. 그 사실만 보고한다.

### 4단계. 폴더 준비

- `ux-kit/projects/` 를 만든다. 세션 리포트가 여기 자동 저장된다.
- `ux-kit/learnings/` 를 만들고, 그 안에 `patterns.md`, `antipatterns.md`, `env-constraints.md` 를
  각각 아래 표 머리글만 담아 생성한다 (이미 있으면 건드리지 마라).

  | 상태 | 발생 | 내용 | 출처 |
  |---|---|---|---|

### 5단계. 검증

실제로 확인한다. 확인하지 않고 "완료했습니다"라고 말하지 마라.

- `.cursor/rules/ux-kit-entry.mdc` 존재 / 첫 줄이 `---` / `alwaysApply: true` 포함
- `ux-kit/UX-UI-RULES.md` 존재
- `ux-kit/context.md` 존재
- `ux-kit/projects/`, `ux-kit/learnings/` 존재
