# 조직 컨텍스트 (context.md)

> **사용법**: 이 파일은 프로젝트의 `ux-kit/context.md` 에 놓인다.
> 커서에서 화면 설계를 요청하면 `ux-ui-design` 규칙이 이 파일을 조직 컨텍스트로 참조한다.
> 다른 도구에서 쓸 때는 규칙 문서와 함께 첨부하면 된다.
> 이 파일에 적힌 것은 **매번 다시 묻지 않는다.**
>
> 이 파일은 프로젝트마다 갈아 끼우는 것이 아니라, **조직·팀 단위로 한 번 만들어 두고 계속 쓴다.**
> 프로젝트별 요구사항은 별도 문서(PRD, 빌드 프롬프트)로 첨부한다.
>
> 채우지 않은 항목은 지침이 그때그때 물어본다. **비워 둬도 동작한다.**
> 해당 없는 항목은 지우지 말고 `해당 없음`이라고 적어라 — 비어 있는 것과 해당 없는 것은 다르다.

---

## 0. 업스트림 레포

세션 리포트와 승격 대상을 이슈로 보낼 곳. 비워두면 `koowoojo/design` 을 쓴다.

```
업스트림 레포: koowoojo/design
```

포크해서 쓰거나 팀별로 분리했으면 여기를 바꿔라.
이슈 전송을 끄고 싶으면 `없음` 이라고 적는다 — 그 경우 리포트는 로컬에만 쌓인다.

## 1. 환경 레퍼토리

**이 절은 "이번 프로젝트의 환경"이 아니라 "우리 조직이 반복해서 쓰는 환경들의 목록"이다.**
타깃 환경은 프로젝트마다 다르므로 여기서 확정하지 않는다.
규칙이 세션 시작 시 이 목록을 번호로 제시하고, 사용자가 하나 고른다.

목록에 없는 환경이 나오면 규칙이 제약을 파악한 뒤 **이 표에 추가를 제안한다.**
쓸수록 선택지가 늘고 조사할 일이 줄어드는 구조다.

| # | 환경 | 핵심 제약 | 금지 문법·기능 | 확인 상태 |
|---|---|---|---|---|
| 1 | 소비자 모바일 앱 (RN/Flutter, iPhone 13 Pro 기준) | 한 손·세로·야간 / A15 10초 / 갤러리 쓰기 | Apple Intelligence UI, 호버 의존, 웹/PWA 전제 | 추정 |
| 2 | | | | |
| 3 | | | | |

**확인 상태**는 셋 중 하나로 적는다. 이걸 비워두면 추정이 사실처럼 굳는다.

- `실측` — 실제 기기·브라우저에서 테스트함
- `문서` — 공식 문서를 확인함
- `추정` — 아직 확인 안 함. **시안에 반영하기 전에 실측으로 바꿔라**

<!--

| 1 | 사내 웹 대시보드 (크롬 최신) | 없음 | 외부 CDN 폰트 금지 (망 분리) | 실측 |
| 2 | 매장 디스플레이 (webOS TV) | 호버 없음(리모컨 포커스) / 시청거리 2~3m | 최신 CSS 선택자 계열 | 추정 |
| 3 | 소비자 모바일 앱 (iOS 16+) | 한 손 조작 / 세로 고정 | - | 문서 |

**이 표가 비어 있어도 동작한다.** 규칙이 그때그때 물어보고, 답한 내용을 여기 추가하자고 제안한다.
첫 프로젝트에서 한 줄, 다음 프로젝트에서 또 한 줄씩 쌓으면 된다.

## 2. 브랜드 / 디자인 토큰

값이 있으면 적고, 없으면 `미정`으로 둔다. 지침은 미정일 때 중립값을 쓰고 "임의값"이라고 밝힌다.

### 색상
```
Primary:
Secondary:
배경:
텍스트 (기본 / 보조):
성공 / 경고 / 오류:
```

### 타이포그래피
```
기본 서체:
대체 서체:
크기 체계 (있으면):
※ 라이선스 주의사항이 있으면 함께 적을 것
```

### 간격 / 모서리
```
간격 단위:
모서리 반경:
```

### 톤 (말로 적어도 됨)
```
예) 정보 밀도를 높게. 여백을 넓게 쓰는 미니멀 스타일은 우리 사용자에게 "빈 화면"으로 읽힌다.
예) 브랜드 컬러는 강조 지점 1~2곳에만. 배경에 깔지 말 것.
```

## 3. 데이터 / 보안 제약

지침의 §0-6(대외비 처리)이 이 항목을 참조한다.

```
[ ] 외부 검색 사용 가능 여부:
[ ] 외부로 나가면 안 되는 정보 유형:
[ ] 시안에 실제 데이터 사용 가능 여부:
[ ] 데이터 저장 위치 제약 (예: 국내 리전만):
```

## 4. 사용자 특성

레퍼런스 선정 기준 2순위(**같은 사용 맥락**)에 직접 쓰인다. 구체적일수록 좋다.

```
주 사용자:
사용 상황:   예) 매장에서 서서, 3초 안에 판단해야 함
디지털 숙련도:
접근성 요구:  예) 40대 이상 비중 높음 — 최소 폰트 크기 상향 필요
```

---

## 5. 기존 자산

이미 있는 것을 적으면 지침이 **일관성 검사(§8-1)**에서 참조한다.

```
디자인 시스템:
컴포넌트 라이브러리:
기존 화면 (참고 가능한 것):
용어 사전:      예) "등록"이 아니라 "저장"으로 통일
```

## 6. 구현 스택

렌더링 시안(§6)이 이 스택으로 바로 옮겨질 수 있게 한다.

```

스타일링 방식:   예) Tailwind / CSS Modules / 순수 CSS
쓰면 안 되는 것:  예) 서버리스 전제 금지, 외부 UI 킷 금지
배포 대상:
```

## 7. 이 조직에서 반복되는 판단 기준

지침이 **추천안을 고를 때** 참조하는 항목이다.
이 파일에서 가장 값이 큰 부분이므로, 프로젝트를 하나 끝낼 때마다 여기에 한 줄씩 추가하라.

```
예) 임원용 화면은 스크롤을 만들지 않는다. 한 화면에 다 보여야 한다.
예) 매장 직원용 화면은 학습 비용이 0이어야 한다. 새로운 상호작용 패턴을 도입하지 않는다.
예) 소비자 앱은 첫 진입에서 로그인을 요구하지 않는다.
```

## 8. 과거 실패 사례

같은 실수를 반복하지 않기 위한 항목. 지침이 시안을 만들 때 이 목록을 피한다.

```
예) 카드 나열형 대시보드 — 정보를 다 보여주지만 무엇을 먼저 볼지 알 수 없어 실패
예) 단계형 마법사 UI — 매장에서 시간이 오래 걸려 사용자가 이탈
```
