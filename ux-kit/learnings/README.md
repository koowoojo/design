# learnings — 승격 대기열

프로젝트에서 나온 교훈을 **1회로 기록**하고, **2회째 발생하면 규칙 본문으로 승격**한다.

## 왜 2회인가

1회는 우연이고 2회부터 패턴이다.
모든 교훈을 즉시 규칙에 넣으면 규칙이 비대해지고, 컨텍스트만 잡아먹으면서 정작 중요한 지시가 묻힌다.

## 기록 방법

각 파일의 표에 한 줄 추가한다. **이미 있는 항목이면 새 줄을 만들지 말고 `발생` 횟수를 +1** 하고
`출처`에 프로젝트를 덧붙인다. 중복 기록하면 승격 시점을 놓친다.

## 승격 방법

`발생`이 2 이상이 되면:

1. `.cursor/rules/ux-ui-design.mdc` 수정 — **추가만 하지 말고 뺄 것을 함께 찾아라**
2. `./build.sh`
3. `CHANGELOG.md` 에 근거와 함께 기록
4. 이 파일의 해당 행 `상태`를 `승격됨(v0.x.y)` 으로 변경 — 지우지 마라. 이력이 근거다
